# KARCAS-DDA

**Documentation-Driven Architecture (DDA) v1.1 — pilot**

> **Статус:** pilot / v1.1
> Это пилотная версия каркаса. Она прошла несколько итераций: анализ реальной экосистемы репозиториев, кросс-анализ четырьмя независимыми моделями, два независимых разбора шаблона, калибровку до v1.1, серию из трёх внешних аудитов с P0-исправлениями и первое реальное применение на проекте-утилите. Каркас **не является окончательным стандартом**. Изменения по результатам реального использования ожидаются и приветствуются.

## Что это

Универсальный каркас проектов, в котором документация определяет систему, а не описывает её постфактум. Ориентирован на работу LLM-агентов и на длительное сохранение контекста между сессиями.

## Быстрый старт

1. Скопировать структуру каркаса в новый проект.
2. Заполнить `docs/VISION.md` (или раздел «Что это» ниже) — цель и границы.
3. Заполнить `CURRENT_STATE.md` — текущее состояние и цель этапа.
4. Добавить запись `D-000000-00` в `DECISIONS.md` — initial setup.
5. Заменить `shaenxxx-commits/karcas-dda` в raw-ссылках `00_ENTRY.md` на актуальные `<USER>/<REPO>`.

## Минимальный профиль

Каркас **не требует** создавать все документы сразу. Для малых проектов (утилиты, скрипты, короткие задачи) достаточно ядра из четырёх документов:

- `README.md` — точка входа для человека и внешнего наблюдателя
- `CURRENT_STATE.md` — что происходит сейчас
- `DECISIONS.md` — принятые решения и основания
- `INVARIANTS.md` — что нельзя нарушать

Всё остальное (`docs/`, `meta/`, `records/`, `PROVENANCE.md`, `ARCHIVE/`) подключается **по необходимости**, а не по умолчанию:

| Документ | Когда подключать |
|---|---|
| `00_ENTRY.md` | Если проект читают LLM-агенты через raw-ссылки |
| `docs/VISION.md` | Если цель и границы не укладываются в README |
| `docs/KNOWLEDGE_STATES.md` | Если работа идёт со статусами знания (OBSERVATION/HYPOTHESIS/VERIFIED) |
| `docs/ARCHITECTURE.md` | Если проект содержит код или инфраструктуру |
| `docs/METHOD.md` | Если есть исследовательская или полевая работа |
| `meta/agent-rules.md` | Если работа идёт с LLM-агентами в длинных сессиях |
| `meta/handoff-protocol.md` | Если контекст передаётся между сессиями или агентами |
| `meta/transitions.md` | Если фиксируются переходы статуса знания |
| `records/` | Если проект накапливает первичные данные |
| `PROVENANCE.md` | Если у значимых утверждений должно быть прослеживаемое происхождение |
| `ARCHIVE/` | Как только появляется устаревшее, что нельзя удалять |

Правило: **лучше 4 работающих документа, чем 15 пустых заготовок.**

## Для людей

Начните с:
1. `README.md` (этот файл)
2. `CURRENT_STATE.md`
3. `docs/VISION.md` (если существует)

## Для LLM-агентов

Читайте строго в порядке, указанном в `00_ENTRY.md` (если он есть в проекте).
Соблюдайте протокол ошибок и конфликтов.
Правила работы агента — в `meta/agent-rules.md` (если существует).

## Структура каркаса

**Корень (минимальное ядро):**
- `README.md` — этот файл, точка входа для человека
- `INVARIANTS.md` — неприкасаемые правила
- `CURRENT_STATE.md` — живое состояние
- `DECISIONS.md` — журнал решений (append-only)
- `PROVENANCE.md` — происхождение утверждений
- `00_ENTRY.md` — точка входа для LLM-агентов

**docs/ (по необходимости):**
- `docs/VISION.md` — цели и границы
- `docs/KNOWLEDGE_STATES.md` — двумерная модель состояний знания
- `docs/ARCHITECTURE.md` — архитектура (для проектов с кодом)
- `docs/METHOD.md` — метод исследования и полевой работы

**meta/ (по необходимости):**
- `meta/agent-rules.md` — правила работы LLM-агента
- `meta/handoff-protocol.md` — протокол передачи контекста
- `meta/handoff-current.md` — текущий снимок передачи
- `meta/transitions.md` — переходы статусов знания
- `meta/open-questions.md` — нерешённые вопросы

**Данные:**
- `records/` — первичные записи
- `ARCHIVE/` — устаревшее, не удаляется
- `templates/` — шаблоны записей (опционально)

## Как вносить изменения

1. Значимое изменение оформляется записью в `DECISIONS.md` со статусом `proposed`.
2. Изменение инвариантов — только через `accepted`-решение (I5).
3. После фиксации `accepted` обновляется `CURRENT_STATE.md` в течение 24 часов (I8).
4. Устаревшее не удаляется, а перемещается в `ARCHIVE/` с датой и причиной (I6).
5. Предложения и замечания — через Issues. Формат свободный, но с указанием: контекст, предложение, ожидаемый эффект.
