# KARCAS-DDA

**Documentation-Driven Architecture (DDA) v1.1 — pilot**

> **Статус:** pilot / v1.1
> Это пилотная версия каркаса. Она прошла несколько итераций: анализ реальной экосистемы репозиториев, кросс-анализ четырьмя независимыми моделями, два независимых разбора шаблона, калибровку до v1.1, серию из трёх внешних аудитов с P0-исправлениями, два реальных применения (nova-registry) и четвёртый раунд аудитов эволюции. Каркас **не является окончательным стандартом**. Изменения по результатам реального использования ожидаются и приветствуются.

## Что это

Универсальный каркас проектов, в котором документация определяет систему, а не описывает её постфактум. Ориентирован на работу LLM-агентов и на длительное сохранение контекста между сессиями.

## Минимальное ядро

Любой проект по KARCAS-DDA начинается с **четырёх документов**:

- `README.md` — точка входа для человека и внешнего наблюдателя
- `CURRENT_STATE.md` — что происходит сейчас
- `DECISIONS.md` — принятые решения и основания
- `INVARIANTS.md` — что нельзя нарушать

Это **фиксированное ядро**, определённое решением `D-20261013-01`. Оно не расширяется без accepted-решения в `DECISIONS.md`.

## Библиотека документов

Всё остальное — **библиотека**, из которой проект берёт нужное по мере появления конкретной потребности. Документ подключается не по типу проекта, а по триггеру.

| Документ | Триггер подключения |
|---|---|
| `00_ENTRY.md` | Работа идёт с LLM-агентом через raw-ссылки |
| `docs/VISION.md` | Цель и границы не укладываются в README |
| `docs/KNOWLEDGE_STATES.md` | Работа идёт со статусами знания |
| `docs/ARCHITECTURE.md` | Проект содержит несколько компонентов, интерфейсы, инфраструктуру |
| `docs/METHOD.md` | Есть исследовательская или полевая работа |
| `meta/agent-rules.md` | Работа идёт с LLM-агентом в длинных сессиях |
| `meta/handoff-protocol.md` | Контекст передаётся между сессиями или агентами |
| `meta/handoff-current.md` | Подключается вместе с `handoff-protocol.md` |
| `meta/transitions.md` | Фиксируются переходы статуса знания |
| `meta/open-questions.md` | Появляются нерешённые вопросы, которые нужно отслеживать |
| `PROVENANCE.md` | У значимых утверждений должно быть прослеживаемое происхождение |
| `records/` + `records/README.md` | Проект накапливает первичные данные |
| `ARCHIVE/` + `ARCHIVE/README.md` | Появляется устаревшее, что нельзя удалять |
| `templates/` | Нужны шаблоны записей (решения, provenance, transition, handoff) |

**Правило:** лучше 4 работающих документа, чем 15 пустых заготовок.

## Состав проекта

Перечень активных документов фиксируется в **точке входа**:
- в `00_ENTRY.md` (раздел «Обязательный порядок чтения»), если он подключён;
- иначе — в `README.md` (раздел «Структура»).

Отдельный реестр не создаётся.

## Быстрый старт

1. Скопировать минимальное ядро в новый проект.
2. Заполнить `README.md` — что это, зачем, как запускать (если есть код).
3. Заполнить `CURRENT_STATE.md` — текущее состояние и цель этапа.
4. Добавить запись `D-000000-00` в `DECISIONS.md` — initial setup.
5. Заполнить `INVARIANTS.md` — либо скопировать из каркаса, либо адаптировать.
6. По мере появления потребности — подключать документы из библиотеки.

## Для людей

Начните с:
1. `README.md` (этот файл)
2. `CURRENT_STATE.md`

## Для LLM-агентов

Если подключён `00_ENTRY.md` — читайте строго в порядке, указанном там.
Иначе — `README.md` → `INVARIANTS.md` → `CURRENT_STATE.md` → `DECISIONS.md`.
Правила работы агента — в `meta/agent-rules.md` (если подключён).

## Как вносить изменения

1. Значимое изменение оформляется записью в `DECISIONS.md` со статусом `proposed`.
2. Изменение инвариантов — только через `accepted`-решение (I5).
3. После фиксации `accepted` обновляется `CURRENT_STATE.md` в течение 24 часов (I8).
4. Устаревшее не удаляется, а перемещается в `ARCHIVE/` с датой и причиной (I6).
5. Предложения и замечания — через Issues. Формат свободный, но с указанием: контекст, предложение, ожидаемый эффект.
