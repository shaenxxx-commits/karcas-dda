# KARCAS-DDA

**Documentation-Driven Architecture (DDA) v1.1 — pilot**

> **Статус:** pilot / v1.1
> Это пилотная версия каркаса. Она прошла несколько итераций: анализ реальной экосистемы репозиториев, кросс-анализ четырьмя независимыми моделями, два независимых разбора шаблона, калибровку до v1.1 и серию из трёх внешних аудитов с последующими P0-исправлениями. Каркас **не является окончательным стандартом**. Изменения по результатам реального использования ожидаются и приветствуются.

## Что это
Универсальный каркас проектов, в котором документация определяет систему, а не описывает её постфактум. Ориентирован на работу LLM-агентов и на длительное сохранение контекста между сессиями.

## Для людей
Начните с:
1. `docs/VISION.md`
2. `CURRENT_STATE.md`

## Для LLM-агентов
Читайте строго в порядке, указанном в `00_ENTRY.md`.
Соблюдайте протокол ошибок и конфликтов.
Правила работы агента — в `meta/agent-rules.md`.

## Структура ядра

**Корень:**
- `00_ENTRY.md` — точка входа для агентов
- `INVARIANTS.md` — неприкасаемые правила (I1–I11)
- `CURRENT_STATE.md` — живое состояние
- `DECISIONS.md` — журнал решений (append-only)
- `PROVENANCE.md` — происхождение утверждений

**docs/:**
- `docs/VISION.md` — цели и границы
- `docs/KNOWLEDGE_STATES.md` — двумерная модель состояний знания
- `docs/ARCHITECTURE.md` — архитектура (рекомендуется для проектов с кодом)
- `docs/METHOD.md` — метод исследования и полевой работы

**meta/:**
- `meta/agent-rules.md` — правила работы LLM-агента (включая формат `MS N`)
- `meta/handoff-protocol.md` — протокол передачи контекста
- `meta/handoff-current.md` — текущий снимок передачи
- `meta/transitions.md` — переходы статусов знания
- `meta/open-questions.md` — нерешённые вопросы

**Данные:**
- `records/` — первичные записи (формат — в `records/README.md`)
- `ARCHIVE/` — устаревшее, не удаляется
- `templates/` — шаблоны записей (опционально)

## Как вносить изменения
1. Значимое изменение оформляется записью в `DECISIONS.md` со статусом `proposed`.
2. Изменение инвариантов (I1–I11) — только через `accepted`-решение (I5).
3. После фиксации `accepted` обновляется `CURRENT_STATE.md` в течение 24 часов (I8).
4. Устаревшее не удаляется, а перемещается в `ARCHIVE/` с датой и причиной (I6).
5. Предложения и замечания — через Issues. Формат свободный, но с указанием: контекст, предложение, ожидаемый эффект.
